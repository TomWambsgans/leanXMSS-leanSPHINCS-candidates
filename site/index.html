leanSphincs

A hash-based signature with the shape of SLH-DSA, retuned for small signatures and cheap verification.

Note (PDF) Code

The scheme

One Merkle tree of one-time keys. The message picks a leaf; that leaf's one-time key signs a few-time key, which signs the message. This is the shape of SLH-DSA-128-24 (NIST SP 800-230), with three changes:

  • a tree of height 26, instead of 22;
  • few-time keys (FORS) of 24 trees of height 10, instead of 6 of height 24;
  • WOTS+C instead of WOTS: 64 chains of length 4 whose positions sum to 120, so no checksum.
Public key32 bytes
Signature5,684 bytes
Verification391 BLAKE2s compressions, the same for every signature
SecurityNIST level 1 (128 bits), with BLAKE2s truncated to 16 bytes

Four modes

Same public key, same signature, same verifier. Only the signer changes.

1. Hardware wallets (Ledger Nano S+)

Lifetime216 signatures
Key generation1.1M compressions, about 34 s
Signing142K compressions, about 4 s, with a 16 KiB cache

The key only builds a subtree of 212 leaves; the signer grinds the randomizer until the message lands in it.

2. Laptops, phones, powerful hardware wallets

Lifetime224 signatures
Key generation287M compressions, about 0.3 s on a laptop
Signing84K compressions with a 1 MiB cache

The same trick with a subtree of 220 leaves.

3. Industry

Lifetime230 signatures
Key generation18.4B compressions, about 20 s on a laptop
Signing421K compressions with a 1 MiB cache, 75K with 1 GiB

The full tree.

4. Threshold (MPC)

Signers3-of-4, key generated without a trusted dealer
Securityagainst 1 malicious operator
Lifetime216 signatures
Key generation1.3 GB of traffic per operator
Signingno MPC once the message is known: about 10 rounds of a few KB

Only hashes of secrets run in MPC, and none depends on the message: the next few-time key is computed in advance (42 MB per operator), and the randomizer is ground until the message lands on it. Prototype in Rust.

Times assume 33K BLAKE2s per second on a Nano S+ and 109 on a laptop. Personal opinion of the author, Tom Wambsgans; subject to change.
